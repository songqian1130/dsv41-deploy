引擎与可复现性

四个方案用的是三代引擎（V2 / V1-legacy / V1-cpumoe）。这一行最容易被忽略，但它决定了 90% 的性能差距。

引擎怎么重建？上游地址 + 我们的补丁，就这两样。 全部信息在 engine/，一共 260 KB，不用存镜像。

别人写的，我们原样复制，地址点开就能下：0001 · 0002 · Containerfile 来自 aiultrayang @29b03af5；x99-stable.patch 来自 LocalFrameLab —— A/B 那 74 行就是它，一字未改。
我们改的，上游从来没发布过，所以没有第三方 URL，这是正常的： 0003 · 0004 · 0005 三个补丁、方案 C 的 local/ 镜像， 再加一份按镜像层反推的 V2 Containerfile。 它们的身份 = 上游 d63af5a 的地址 + 仓库里这份 patch，不是丢件。

47.6 GB 里只有 191 MB 不能保证「编出来一模一样」（那 5 个编译产物 .so； 源码在、随时能重编，只是编译器版本没钉死）， 其余全是「记得住地址就能重新下载」的公开资源。 正常还原走 engine/<引擎>/build.sh（40~90 分钟，需外网）； 想沿用历史基准，再把那 191 MB 覆盖回去；完全没有外网才用整包（20~25 GB，永不进 git）。

参数

可以直接对着改。完整启动命令在各方案目录的 run.sh。

怎么部署

目标机器只需要 Docker + nvidia-container-toolkit + 模型权重。

git clone <this-repo> dsv41-deploy && cd dsv41-deploy

./deploy.sh pp5-fast                  # 方案 A：5 卡生产
./deploy.sh pp4-t16                   # 方案 B：4 卡，GPU4 留给 ComfyUI
./deploy.sh pp5-legacy --engram ram   # 方案 C：V1 旧引擎，engram 放内存

./deploy.sh pp5-fast --dry-run        # 只看要执行的 docker 命令
./deploy.sh pp5-fast --stop           # 停掉

模型路径默认 /run/media/xpz/models/DeepSeek-V4.1-Flash-1017-official， 用 --model 或 DSV41_MODEL 覆盖。首次启动 4~9 分钟，脚本会自己等 /health。

口径（只有按同一批 nonce、同一套 cases_v1 跑出来的数字才能这样并排比）

  1. 单流 tok/s = 服务端 completion_tokens ÷ (总时长 − TTFT)；四档均值是四个 real 用例的算术平均。
  2. 同一配置三轮之间的极差通常 5~7%，所以差值 <5% 一律记「噪声内」，不写「提升」。
  3. 跨方案比较必须同一批 nonce；不同批 nonce 的绝对值不能直接相减。
  4. 冷启动首轮丢弃；不许用高熵用例单独下结论。
  5. 代价必须写：GPU4 是否被占、主机内存吃了多少、启动多久。

原始数据：bench/results.jsonl（单流）· bench/capacity.jsonl（并发/容量/prefill）。 页面由 tools/build_index.py 从各方案 meta.json 生成，别手改这个 HTML。
