# bench —— 性能测试的唯一入口

> 任何速度数字都必须来自这里的脚本，并且落在 `results.jsonl`。
> 手搓的临时脚本算出来的数一律不准（2026-11-16 用 `reasoning_content` 抓流式字段，
> 实际字段是 `reasoning`，算出 86 tok/s；真实值 28）。**这就是为什么这里只留两套脚本。**

## 1. 两个脚本

| 脚本 | 用途 | 输出 |
|---|---|---|
| `run_cases.py <label> <nonce> --set real` | 标准四档（code / json / zh / math），一次跑完 | 追加 `results.jsonl`，带启动参数快照 |
| `ab_rank3.sh [轮数] [A卡序] [B卡序]` | 卡位 A/B：固定前三段，只换 rank3 的卡 | 两组各一轮启动 + N 轮标准用例 |

用例本身在 `cases_v1.json`，**不要改它**。改了等于换了一把尺子，历史数据全部作废。

## 2. 铁律（每条都是踩坑换来的）

| # | 规则 | 为什么 |
|---|---|---|
| 1 | **先跑 3 轮热身，只取第 4~6 轮** | 实测同一配置 44.1 → 48.3 → 51.5 → 52.4 → 53.3 → **54.1**，第 6 轮才稳。只跑 1~2 轮会误判成"环境退化" |
| 2 | **端到端看 `tps_wall`，不看 `tps_decode`** | `tps_decode` 是引擎自报的纯 decode 时间，不含排队与首字；方案卡上的历史数字是 wall 口径 |
| 3 | **`wall=` 后面是 tok/s，不是秒** | `wall=59.98` 意思是 59.98 tok/s。看成"59.98 秒"会推出"端到端只有 10 tok/s"这种假问题 |
| 4 | **改任何启动参数前先 `diff ~/dsv41-repo-test/run-pp4.sh.bak-131k`** | util 从 0.99 误改成 0.92，槽位 4320→3320，端到端 54→48，被当成环境退化查了一下午 |
| 5 | **同一组对比必须共用同一套启动参数** | 卡位对比时如果 rank3 从 GPU4（150W）换到 GPU0（250W），功耗就成变量了 |
| 6 | **B 方案启动前先停 ComfyUI** | 引擎要求 `MemAvailable ≥ 64+138+8+16 = 226 GiB`，且这个检查在分配过程中逐块执行 |
| 7 | **不要在 GPU4 上做大块 PCIe 搬运 + kernel 重叠** | 会硬冻结整机（`docs/GPU4-HANG.md`）。P2P 大块拷贝也算 |

## 3. 实验矩阵

「已测」= 有 `results.jsonl` 记录；「待测」= 计划中；「已证伪」= 测过且方向被否决，**不要再重复测**。

### 3.1 卡位（KV 131k · util 0.99 · PP4 `[6,6,7,21]`）

| 组 | GPU 顺序 | rank3 落在 | 状态 | 端到端 tok/s |
|---|---|---|---|---|
| A0 | `0,1,2,3` | GPU3 | ✅ 已测（11-14 + 11-16 复现） | **53.6 / 54.1** |
| A1 | `1,2,3,4` | **GPU4** | 🟡 未收敛（第 5 轮 50.0） | 50.0 ~ 51.1 |
| A2 | `1,2,3,0` | GPU0 | ⬜ 待测 | — |

> A1 vs A2 是控制变量最干净的一组：前三个 rank 固定 GPU1/2/3，只换最后一段。
> 功耗墙必须统一（脚本会自动把五卡都设 150W）。
> 判读：A1 ≈ A2 → GPU4 无问题，A0 vs A1 的 6% 是热身；A1 明显低 → GPU4 作为 rank3 有代价。

## 4. 硬件基线（2026-11-16 实测，五卡逐项对比）

容器内 dev0~3 对应宿主 GPU1/2/3/4。测法见 `docs/GPU-HARDWARE.md`。

| 宿主 GPU | fp16 算力（8192³，两次交错） | H2D 带宽（64MB） | H2D 延迟（4KB） |
|---|---|---|---|
| GPU1 | 157.7 / 157.5 | — | — |
| GPU2 | 159.0 / 158.6 | 1.47 GB/s | 18.3 μs |
| GPU3 | 158.7 / 158.6 | 1.51 GB/s | 19.0 μs |
| **GPU4** | **160.3 / 159.4** | **1.51 GB/s** | 19.0 μs |

**五卡规格逐项相同**（CMP 170HX · 65536 MiB · SM 上限 1695 MHz · 显存 1728 MHz · Gen2 x4）。
「GPU4 性能差」在硬件层面不成立——它的算力和带宽都是最高的一档，只有 4KB 小包延迟比 GPU2 高 3.8%。

## 5. results.jsonl 字段

```jsonc
{
  "version": "cases_v1",
  "cases_sha256": "...",        // 用例哈希，确保尺子没变
  "nonce": "run1234",           // 每轮不同，防前缀缓存
  "label": "A1_gpu4",           // 建议 <组>_<条件>
  "run_index": 1234,
  "ts": "2026-11-16T16:00:00",
  "config": {                   // ← 2026-11-16 新增，没有这一项的数一律不可比
    "gpu-memory-utilization": "0.99",
    "max-model-len": "131072",
    "kv-cache-tokens": "131072",
    "pipeline-parallel-size": "4",
    "additional-config": "{...cpu_threads...}",
    "speculative-config": "{...k...}"
  },
  "cases": [
    {"case": "code_python", "tps_wall": 63.2, "tps_decode": 70.1,
     "ttft_s": 0.76, "valid_cold": true, "acc_per_draft": 0.72}
  ]
}
```

**label 命名约定**（避免 `?` / `dspark` / `conv` 这种无法追查的标签）：

```
<方案>_<组>_<条件>        例：pp4t16_A1_gpu4_131k_u099
```

## 6. 跑之前检查三件事

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:9010/health   # 200
nvidia-smi --query-gpu=index,power.limit,memory.used --format=csv        # 功耗墙/卡位对不对
free -g | head -2                                                        # available 够不够
```

`run_cases.py` 开跑时会打印一行 `[config]`，**先看这行确认自己在测什么**，再让它跑完。
