# 四个方案怎么选

一句话：**要快选 A，要空出一张卡选 B，要快速重启或做对照选 C，怕 GPU4 冻机选 L。**

| | [A · pp5-fast](pp5-fast/) | [B · pp4-t16](pp4-t16/) | [C · pp5-legacy](pp5-legacy/) | [L · pp4-cpumoe](pp4-cpumoe/) |
|---|---|---|---|---|
| 引擎 | 新引擎 V2 · dspark k=5 | 新引擎 V2 · dspark k=5 | 旧引擎 V1 · 无投机 | 旧引擎 V1 · ngram k=3 · CPU 专家 |
| 卡 | 5 | 4（GPU4 空出） | 5 | 4（**GPU3** 空出，GPU4 给引擎） |
| 单流 tok/s | **82.5** | 60.9 | 43.5 | 26.4（zh 单轮，非四档均值） |
| 4 路并发聚合 | **135.6** | 未测（3 路 70.5） | 43.9（3 路，不扩展） | 未测（6 路 ≈31） |
| 22k TTFT | 9.40 s | 13.71 s | 6.45 s（ram）/ 11.9 s（ssd） | 未测（短请求就已 14.85 s） |
| 启动 | 8:57 | ~9 min | **4:30** | 7:50 |
| 主机内存 | 190 GiB | 150 GiB | 30 / **189** GiB | **110 GiB**（engram 走盘） |
| 镜像可拉取 | ⚠️ 未验证（需外网） | ⚠️ 未验证（同 A） | ⚠️ 从未推送，配方在仓库里 | ⚠️ 同 C，overlay 可从 GitHub 重建 |
| 判定 | ✅ 生产 | ⚠️ 有条件 | 🕘 兜底 | ⚠️ 兜底（**唯一不冻机**） |

## 四个典型场景

**日常跑，不需要 GPU4** → A。它没有任何妥协：5 卡全用、覆盖率 93.96%、4 路并发还能再涨 40%。

**要同时跑 ComfyUI / 训练小模型** → B。代价写得很清楚：单流 −26%、22k TTFT +46%，
换来一张完整的 64 GB 卡。**注意长文 prefill 是它最痛的地方**（TTFT 13.7 s）。

**只想 4 分钟起一个能用的服务、或者要跟新引擎做对照** → C。
它慢一半，但启动快一半，而且没有投机解码，**输出速度与内容完全无关**（永远 43.5），
做基准对照时这条很有用 —— 它是唯一一个"输入什么都不会让数字变"的方案。

**GPU4 在场又不想整机冻结** → L（2026-11-16 新增）。
它把 9 层路由专家丢给 CPU、engram 189 GiB 走 NVMe，GPU4 只承载 PP3 的小包流量，
所以"大块 PCIe 搬运 + GPU 计算重叠"这个死机条件在 GPU4 上不再成立。
代价是慢：zh 单流 26.4 tok/s、短请求 TTFT 14.85 s、6 路并发聚合只有 31。
**它是兜底，不是主力。**

> 2026-11-16 补记：L 的并发代价曾被误判成"主机竞争"，实测是 GPU3 功耗墙 150 W 把 SM 压到
> 1035 MHz。引擎 6 路满载对 H3 视频的真实影响只有 +1.9 s（+1.5%）。见 `.workbuddy/memory/2026-11-16.md`。

## 不能同时跑

四个方案抢同一批卡和同一份主机内存（A 的 138 GiB 专家 bank、C 的 189 GiB pinned 都在这 247 GiB 里）。
切换前先 `--stop` 掉另一个。

## 每个目录里有什么

```
<方案名>/
├── README.md     方案卡（引擎 / 前置 / 部署 / 性能六段 / 排障 / 已验证环境）
├── deploy.sh     一键部署：预检 → 起容器 → 等 /health → 打印端点
├── run.sh        只做 docker run，参数可用环境变量覆盖
└── meta.json     数据源，tools/build_index.py 用它生成根目录 index.html
```
